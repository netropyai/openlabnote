연구노트, 쓰지 말고 만드세요

AI 코딩 세션의 프롬프트와 git 커밋이 이미 그날의 기록입니다. openlabnote가 그 기록을 모아 하루 한 장의 연구노트(md)로 정리합니다 — 당신의 Claude·Codex 구독으로, 추가 비용 없이.

$ npx openlabnote
$ oln today
① 수집 git 8커밋 · claude-code 12세션 → 과제 2건 매핑
② 작성 엔진 claude -p (41s)
③ 검사 통과 — 불릿 9 · 주제 3
✓ 저장 ~/openlabnote/neural-rendering/2026-08-21.md
$
§3 how it worksatuin스텝 3개로 압축. 각 스텝에 실제 명령·개념 하나씩.
01 · 수집기록은 이미 있습니다

Claude Code·Codex 세션, git 커밋을 날짜별로 수집합니다. 원격 개발 서버도 SSH로 — serverA:~/dev/repo.

02 · 작성내 구독의 AI가 씁니다

요약·작성은 당신의 Claude/Codex 구독이 수행합니다. API 키도, 추가 비용도 없습니다. 커밋은 "무엇을", 프롬프트는 "왜"를 남깁니다.

03 · 검사·저장내 폴더의 마크다운으로

포맷 검사(oln lint)를 통과한 노트가 내가 지정한 폴더에 md로 쌓입니다. 열람·수정·백업·git 관리 전부 자유.

자주 묻는 질문

쓰고 있는 전자연구노트 서비스가 있는데 같이 쓸 수 있나요?

네. openlabnote는 노트를 만드는 도구라서 어디에 제출할지는 자유입니다. 노트는 md 파일로 남고, 제출용 export(일자별 PNG·기간 PDF)가 로드맵에 있어 쓰던 서비스에 그대로 올리면 됩니다.

세션 내용이 외부로 전송되나요?

아니요. raw 수집 데이터는 로컬에서만 읽혀 요약에 쓰입니다. 요약(작성) 자체도 당신의 하네스 구독 안에서 실행됩니다.

AI 사용 비용이 따로 드나요?

아니요. 이미 쓰는 Claude Code/Codex 구독으로 동작합니다. 노트 1건에 보통 30~60초의 세션이 쓰입니다.

이것만으로 지침상 전자연구노트가 되나요?

로컬 md는 훌륭한 기록이지만, 지침의 3요건(전자서명·시점기록·위변조 확인)은 별도 인프라가 필요합니다. 그 부분이 OpenLabnote Cloud(준비 중)이고, 그때까지는 기존 서비스에 업로드하는 방식을 권합니다.

노트 품질을 제가 통제할 수 있나요?

네. 작성 지침이 마크다운 파일이라 oln instructions write --edit로 내 문체·규칙으로 바꿀 수 있고, 포맷 린터가 형식을 강제합니다.
